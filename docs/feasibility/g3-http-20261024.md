## Routes

The [application](../../pact/http.py) exposes the existing participant services through these routes.

| Method | Path | Behavior |
| --- | --- | --- |
| POST | `/api/login/challenge` | Bind the public key to a browser challenge. |
| POST | `/api/login/finish` | Verify the device signature and set the session cookie. |
| POST | `/api/logout` | Revoke the session and clear its cookie. |
| POST | `/api/stop` | Stop permitted new actions for the authenticated Principal. |
| GET | `/api/notifications` | Read participant notices with optional `after` and `limit` parameters. |
| GET | `/api/transactions/{transaction_id}` | Read the participant's transaction snapshot. |
| GET | `/api/transactions/{transaction_id}/input` | Download the participant's permitted input bytes. |
| GET | `/api/transactions/{transaction_id}/output` | Download output bytes when the existing payment permission allows delivery. |

Construct `Application(users)` with the existing `UserService` instance.
This adapter does not create a network listener or read credentials.
The current routes do not expose account registration, agent signing, operator access, or payment dispatch.
Image intake and evidence export still require their existing internal service interfaces.

## Request boundary

The application requires HTTPS and the configured Host.
It does not trust `X-Forwarded-Proto` to establish HTTPS.
A TLS server must supply the verified WSGI scheme and Host.
Every POST requires the exact configured Origin.
Authenticated mutations also require the session-bound `X-Pact-CSRF` value.
Login completion requires the browser challenge cookie and device signature.
The browser retains the private signing key.
The adapter returns session tokens only through secure HTTP-only cookies.
It returns the CSRF value separately for authenticated browser requests.
No response includes the browser bearer token.

JSON bodies require the exact `application/json` content type and at most 65536 bytes.
The parser rejects duplicate keys, nonfinite constants, unexpected fields, invalid UTF-8, and truncated bodies.
Pagination accepts only bounded decimal parameters.
The adapter rejects duplicate protected cookie names and control characters in cookie headers.
It rejects query parameters on other routes.
Errors do not expose exception text, payment tokens, or tracebacks.
All responses disable caching, content sniffing, framing, and referrer disclosure.
File responses use fixed attachment names and an opaque binary content type.
